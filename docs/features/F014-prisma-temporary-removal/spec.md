## 목적

현재 사용되지 않는 Prisma 의존성을 제거해 배포 환경(Node 버전 제약) 문제를 해소하고, 필요 시 다시 추가할 수 있는 기반을 마련한다.

---

## 사용자 스토리

### US-1: 배포 환경 호환성 확보

**As a** 운영자  
**I want** Prisma 의존성을 제거해 Node 버전 제약을 피하고  
**So that** Coolify 배포가 안정적으로 진행된다

**Acceptance Criteria:**
- [ ] 배포 환경에서 Node 버전 오류가 발생하지 않는다
- [ ] 로컬 개발 흐름에 큰 변경이 없다

### US-2: 필요 시 재추가 가능

**As a** 개발자  
**I want** Prisma를 나중에 다시 추가할 수 있도록  
**So that** DB 기능이 필요해질 때 빠르게 복구할 수 있다

**Acceptance Criteria:**
- [ ] Prisma 재추가 절차가 문서화된다

---

## 기능 요구사항

### FR-1: Prisma 의존성 제거

`prisma`, `@prisma/client` 및 관련 스크립트를 제거한다.

### FR-2: 문서 동기화

프로젝트 문서(README/PRD/헌장 등)에서 Prisma 관련 내용을 현재 상태에 맞게 정리한다.

### FR-3: 재추가 가이드

Prisma 재도입 시 필요한 단계(의존성/스키마/스크립트)를 문서로 남긴다.
