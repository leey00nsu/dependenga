# Feature Spec: 랜딩/결과 v2 톤 리디자인

> 이 템플릿을 복제하여 새 기능 스펙을 작성합니다.
> 기술 스택은 여기서 다루지 않습니다. (plan.md에서 다룸)

---

## 개요

- **기능 ID**: F009
- **기능명**: landing-result-v2
- **작성일**: 2026-01-12
- **상태**: Approved

---

## 목적

- 최신 디자인 산출물(landing-v2/result-v2/component-v2)에 맞춰 랜딩/결과 화면의 전반적인 톤을 통일한다.
- 친근하고 밝은 브랜드 톤으로 첫 인상을 개선하고, 랜딩 분석/결과 공유 액션의 가시성을 높인다.

---

## 사용자 스토리

### US-1: 첫 진입 사용자의 브랜드 인지

**As a** 첫 방문 사용자  
**I want** 랜딩에서 브랜드 톤이 명확하게 전달되길  
**So that** 서비스가 무엇인지 직관적으로 이해할 수 있다.

**Acceptance Criteria:**
- [ ] 랜딩 화면이 `docs/designs/landing-v2.png`의 톤과 레이아웃을 반영한다.
- [ ] 메인 로고 이미지는 `landing-image`를 사용한다.

### US-2: 분석 결과 화면의 일관성

**As a** 결과를 확인하는 사용자  
**I want** 랜딩과 동일한 비주얼 톤으로 결과가 보이길  
**So that** 서비스 흐름이 일관되게 느껴진다.

**Acceptance Criteria:**
- [ ] 결과 화면이 `docs/designs/result-v2.png`의 톤을 반영한다.
- [ ] 배경은 `background-v2`를 사용한다.

---

## 기능 요구사항

### FR-1: 공통 배경/톤 적용

- 랜딩/결과 페이지 모두 `background-v2` 이미지를 배경으로 사용한다.
- 전체 색상 톤은 component-v2의 블루 계열 스타일을 기준으로 한다.

### FR-2: 랜딩 페이지 구성 리팩토링

- 메인 로고는 `landing-image`를 사용한다.
- 입력 영역(파일 업로드, 탭, 텍스트 입력, 분석 버튼)은 component-v2 스타일을 반영한다.
- 기존 다크 테마 기반 장식(글로우/그리드/비네트)은 제거한다.

### FR-3: 결과 페이지 구성 리팩토링

- 랜딩과 동일한 브랜드 톤/배경을 사용한다.
- 결과 페이지의 주요 컴포넌트(패널, 배지, 버튼)는 component-v2 스타일로 변경한다.
- 결과 페이지의 공유 버튼은 현재 위치(헤더 영역)를 유지한다.

### FR-4: 컴포넌트 스타일 정합성

- 버튼/토글/카드/입력 필드가 component-v2 시각 스타일과 유사한 계층을 가진다.
- 레이아웃은 데스크톱/모바일에서 깨지지 않는다.

### FR-5: 3D 젠가 블럭 스타일 동기화

- 3D 젠가 블럭의 색감/광택/테두리 톤이 `docs/designs/result-v2.png`의 블럭 스타일과 일치한다.
- 안전/위험 상태가 시각적으로 구분되며, component-v2 배지 컬러를 그대로 사용한다.

---

## 비기능 요구사항

- **성능**: 기존 동작 대비 렌더링 성능 저하가 없어야 한다.
- **접근성**: 텍스트 대비와 상호작용 상태가 명확해야 한다.

## 화면/플로우

- 흐름은 기존과 동일(입력 → 분석 → 결과)하되, 시각 톤만 v2로 전환한다.

---

## 엣지 케이스

- 매우 긴 패키지명이 있는 경우 카드/배지 레이아웃이 깨지지 않는다.
- 결과 데이터가 없거나 오류일 때도 v2 톤의 안내 UI가 표시된다.
- 모바일에서 입력 영역과 버튼이 겹치지 않는다.
- 3D 블럭의 색상 대비가 배경과 섞이지 않으며 식별 가능하다.
