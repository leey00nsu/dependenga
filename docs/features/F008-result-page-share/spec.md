## 목적

- 입력 화면과 결과 화면을 명확히 분리해 흐름을 단순화
- 결과를 URL로 공유해 누구나 동일한 분석 결과를 재현 가능
- 서버 저장 없이도 공유 가능한 결과 링크 제공

---

## 사용자 스토리

### US-1: 입력과 결과 화면 분리

**As a** 사용자  
**I want** 입력 화면(`/`)과 결과 화면(`/result`)을 분리해  
**So that** 흐름이 명확하고 공유가 쉬워진다

**Acceptance Criteria:**
- [ ] `/`는 입력/파싱 UI만 담당한다
- [ ] `/result`는 쿼리스트링 기반 데이터로 분석 결과를 표시한다

### US-2: 공유 가능한 결과 URL

**As a** 분석 결과를 공유하려는 사용자  
**I want** 결과를 URL로 복사해 공유하고  
**So that** 누구나 동일한 결과를 확인할 수 있다

**Acceptance Criteria:**
- [ ] 의존성 목록만을 압축해 쿼리스트링에 포함한다
- [ ] URL을 복사해 열면 동일한 결과가 재현된다
- [ ] 길이가 4000자를 초과하면 경고를 표시하고 진행 여부를 선택할 수 있다

---

## 기능 요구사항

### FR-1: 라우팅 분리

- `/`는 입력/파싱만 담당하고 결과 렌더링은 하지 않는다
- `/result`는 쿼리스트링 데이터를 복원해 분석을 실행한다

### FR-2: 결과 공유용 쿼리스트링

- 저장 대상은 의존성 목록(이름/버전/isDev)만 포함한다
- `lz-string`의 `compressToEncodedURIComponent`/`decompressFromEncodedURIComponent`를 사용한다
- 복원 실패 시 오류 메시지를 표시한다

### FR-3: FSD 패턴에 맞는 뷰 분리

- `views` 레이어를 FSD 구조에 맞게 분리한다
- 입력/결과 화면 구성은 `widgets` 또는 `pages` 레이어로 이동한다

---

## 비기능 요구사항

- **성능**: 로딩/복원 지연이 체감되지 않도록 한다
- **보안**: 서버 저장 없음 (클라이언트 URL 공유만)
- **접근성**: 복사 버튼/오류 메시지는 스크린리더에 인지 가능

---

## 화면/플로우

- `/` 입력 → 의존성 목록 압축 → `/result?d=...` 이동
- `/result`에서 데이터 복원 → 분석 실행 → 결과 표시

---

## 엣지 케이스

- 쿼리스트링 복원 실패 시: 오류 화면 + `/`로 돌아가기 안내
- URL 길이 4000자 초과 시: 경고 표시 후 사용자 선택
