## 목적

디자인 시안(`docs/designs/landing.png`)과 현재 랜딩페이지 UI 간의 불일치를 해소하여
브랜드 일관성과 초기 사용자 신뢰/전환율을 개선한다.

---

## 사용자 스토리

### US-1: 디자인과 동일한 랜딩 경험

**As a** 방문자  
**I want** 디자인 시안과 일치하는 랜딩페이지를 보고  
**So that** 제품 이해도와 신뢰를 높이고 다음 행동(CTA)으로 이동할 수 있다

**Acceptance Criteria:**
- [ ] 섹션 구성/순서/레이아웃이 `landing.png`와 일치한다
- [ ] 색상/타이포/버튼 스타일이 디자인 시안과 일치한다
- [ ] 주요 CTA의 위치와 시각적 우선순위가 시안과 일치한다

### US-2: 모바일에서도 동일한 경험

**As a** 모바일 사용자  
**I want** 작은 화면에서도 레이아웃이 무너지지 않고  
**So that** 콘텐츠를 쉽게 읽고 CTA를 사용할 수 있다

**Acceptance Criteria:**
- [ ] 모바일 기준에서 텍스트/버튼이 읽기 쉬운 크기와 간격을 유지한다
- [ ] 주요 섹션이 논리적 순서로 표시되고 스크롤 흐름이 자연스럽다

---

## 기능 요구사항

### FR-1: 레이아웃/구성 반영

`docs/designs/landing.png` 기준으로 섹션 구성, 그리드, 여백, 정렬을 반영한다.

### FR-2: 비주얼 스타일 반영

색상, 타이포그래피, 버튼/카드 스타일, 아이콘/일러스트 스타일을 시안과 동일하게 적용한다.

### FR-3: 에셋 적용 및 최적화

디자인에 포함된 이미지/일러스트를 적용하고, 웹 최적화(사이즈/포맷)를 유지한다.

### FR-4: 반응형 동작 정의

주요 브레이크포인트에서 섹션 정렬/스택/간격을 정의하여 시안 의도를 유지한다.

### FR-5: package.json 업로드 지원

package.json을 붙여넣기뿐 아니라 **드래그 앤 드롭 업로드**로도 입력할 수 있어야 한다.

---

## 비기능 요구사항

- **성능**: 랜딩 초기 로딩(LCP) 성능을 기존 대비 악화시키지 않는다
- **보안**: 정적 페이지 변경만 수행 (인증/권한 변경 없음)
- **접근성**: 색 대비, 시맨틱 태그, 포커스 상태를 유지한다
